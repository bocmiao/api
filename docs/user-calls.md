# 管理员用户调用详情

在「管理 → 用户」点击某一行的「调用详情」，按北京时间自然日选择日期，或使用前一天、后一天、今天。表格列出全部接口，不做 Top N 截断，并显示合计、成功、4xx 和 5xx。

只统计原有日志入口已归属 `user_id` 的 HTTP 请求：多个 API Key 与登录会话合并；含缓存；批量请求计一次 HTTP 调用，额度可扣多次；5xx 计调用但退额度；已识别 Key 的 403 保留原口径。429 单独记限流，不混入详情调用；无效 Key、匿名、公开接口、404、405、OPTIONS 和内部检测不归入用户详情。成功沿用现有统计的 `<400` 定义（含重定向）。用户列表的「今日基础额度消耗」来自 `usage_daily`，不含兑换码额外次数。

新请求优先使用注册路由模板。历史数据沿用日志中的路径；旧日志没有 HTTP method，无法恢复方法。详情不会返回 Key、密码哈希、IP、请求参数或错误正文。

`user_calls_daily` 以 `(user_id, day, path)` 为主键永久保存 calls/ok/e4xx/e5xx。SQLite `AFTER INSERT` 触发器与 `request_log` 插入原子提交；按完成写日志时的时间归日，日志清理和 Key 删除或重置不会删除汇总。首次启动在 `BEGIN IMMEDIATE` 事务内回填剩余日志、写 `user_calls_meta` 迁移标记并建立触发器，重启不重复回填。HTTP 入口只尝试写日志一次；若写入失败，原日志与日汇总一起回滚并输出服务错误日志，仍发送原业务响应、不误退已成功请求的额度。注册账号使用持久 ID 高水位，避免注销后新账号复用 ID、继承旧历史。

迁移当天和更早的历史一律标为可能不完整：曾经删除的日志无法恢复。历史空数据表示「没有保留的记录，无法确认是否无调用」；迁移后完整自然日空数据表示「当天无调用」；请求失败显示加载失败及重试按钮。

只读接口：`GET /admin/users/:id/calls?day=YYYY-MM-DD`。先管理员鉴权，再校验安全正整数 ID 和真实日期；默认北京时间今天。用户不存在返回 404；查询参数化；响应 `Cache-Control: no-store`。前端只允许最新请求更新当前仍打开的弹窗。

验证：`node --test test/user-calls.test.js`，完整回归 `npm test`。当前云机器浏览器验收脚本和结果保存在忽略目录 `data/onboarding/`，运行 `node data/onboarding/browser-check.mjs`（使用环境预装 Playwright 与 Chromium，不属于应用依赖）。
