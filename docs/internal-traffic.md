# 内部测试统计隔离

「管理 → 统计」默认使用**业务**口径，排除记录时已明确标记的内部测试。顶部可切换到**内部测试**或**全部**；趋势、KPI、接口、调用方、来源、错误、限流和 CSV 使用同一口径。请求明细显示保存的分类及依据，日志按原有保留期保留，不因分类删除。

## 可信身份配置

仅部署方可通过服务器环境明确配置已有身份；默认均为空：

```dotenv
STATS_INTERNAL_USER_IDS=
STATS_INTERNAL_KEY_IDS=
```

填写数据库中已经存在的正整数 ID，多个 ID 用逗号或空白分隔。配置账号代表该账号后续所有已识别调用均用于内部测试；配置 Key 仅代表这个已有 Key，其所属用户的其他 Key 和网页登录调用继续按各自规则分类。已有账号、Key 的创建、权限、配额、来源规则和密钥均不修改，也不会创建新的 Key。

配置在服务启动时解析。在后台点击「查看内部标记配置」可只读核对生效的账号、Key 标签及未生效的 ID。空配置不会排除任何身份；不存在的身份不会生效。格式错误会在启动时给出不含配置原文的错误。ID 须为安全范围内的正整数，查询使用参数绑定。

**管理员角色不自动代表内部测试。** localhost、IP、域名、Origin、Referer、User-Agent、`X-Internal-Test`、`traffic` 查询参数等都不能将调用变成内部测试。已有凭证仍由原认证流程校验，再按服务器配置分类；错误 Key 不能冒认身份。已识别但被 Key 的来源/范围/停用策略拒绝的请求，可依据已识别的配置身份记录内部失败。

Key 初次绑定会在统计专用表中保存 ID、用户 ID 和不可逆指纹，防止删除后复用 ID 或重置 Key 时静默沿用旧标记。指纹不会返回接口或界面；Key 不存在或已变更时，该 Key 规则不再生效，未命中其他有效配置的新调用按业务处理，并在配置视图提示未生效，需部署方核对现有身份。已开始请求使用认证阶段捕获的分类快照，进行中的请求不会因随后配置/Key 变化而被重新解释。

部署方明确确认变更后的同一个已有 Key 仍专用于测试时，可先把该 ID 从统计名单移除并重载配置，再明确重新加入以建立新绑定。只重载相同名单不会静默重绑；此操作仅涉及统计配置，不需要重建凭证或更改 Key 权限。已保存日志的分类不随重新绑定改变。

本次实现没有为任何真实账号或 Key 启用配置，没有修改生产环境文件，也没有接触生产数据库。部署方后续应只填写确定专用于测试的已有身份，混合业务账号宜只配置其专用测试 Key。

## 历史与统计口径

| 保存分类 | 意义 | 业务 | 内部测试 | 全部 |
| --- | --- | --- | --- | --- |
| `business` | 记录时未命中明确内部身份 | 包含 | 排除 | 包含 |
| `internal` | 认证身份命中服务器账号/Key 配置 | 排除 | 包含 | 包含 |
| `legacy` | 升级前没有可信分类标记 | 包含 | 排除 | 包含 |

原始明细增加 `traffic` 与 `traffic_basis`，后者为 `configured_user`、`configured_key`、`not_configured` 或 `legacy_unclassified`。保存后不会因环境配置增删自动重分类。

旧日志、已保留来源日汇总和原统计汇总没有当时的可信测试标记，全部按 `legacy` 保留。不会按现在的账号名单、IP 或请求头反推过去的调用，也不会把未分类历史宣称为纯业务。界面显示分类开始时间和历史说明；配置生效前已经混入的测试量无法靠这次升级可靠清除。原始日志已过期的历史更不能恢复身份。

已分类调用数满足业务 + 内部测试 = 全部。独立 IP/活跃用户在两种口径中可能重叠，不能相加。注册、账号总数及留存队列按当前显式账号名单分组；只标记一个测试 Key 不会把其整个所属账号移出业务注册指标。

429 沿用原有防刷策略，不写逐请求明细，但按可信分类记录独立限流汇总。内部测试同样消耗原有额度，5xx 退额规则保持原样。个人 `/account/usage` 和配额信息展示实际使用量；统计隔离不等于免费调用。

## 聚合与查询

事务迁移新增分类汇总并复制旧汇总为 legacy；`source_daily` 增加分类主键维度。迁移标记、表结构、来源触发器及旧值复制在一个 SQLite 事务内完成，重复执行不重复累加。原始日志、分类来源汇总、分类用户汇总由同一次插入原子提交。按小时/天的内存计数在同一 flush 事务中写入原全部汇总及分类汇总，失败时保留待写数据重试，避免半写与重复。

业务和内部的延迟分桶、最大耗时、缓存、字节等均独立累加，不能用全部的最大值减内部的最大值。分类小时表沿用 `STATS_HOURLY_DAYS`（默认90天），来源日汇总沿用 `SOURCE_RETENTION_DAYS`（默认365天），原始明细沿用 `LOG_RETENTION_DAYS`（默认30天）。原始日志清理不会扣减日汇总或累计分类计数。

管理员分析接口、`/admin/stats` 和 `/admin/users/:id/calls` 接受 `traffic=business|internal|all`，默认 business；管理员鉴权先于参数校验。作用域用 AsyncLocalStorage 隔离，查询表名由固定白名单映射到只读视图，参数仍绑定，不能用并发请求污染另一种口径。

公开首页、文档、卡片及状态页的调用数字固定为业务口径，客户端传入 `traffic=internal/all` 不会暴露内部数量；健康检查本身维持独立语义，已明确内部测试的失败不用于触发业务流量故障。旧的历史故障无法据此自动重分类。用户管理中的实际配额信息仍保持真实消耗。

`GET /admin/analytics/traffic-config` 仅管理员可访问，返回已有身份的 ID、邮箱/标签与未生效 ID，不返回 Key、Key hash、指纹或其他凭据。该界面只读，不提供创建凭证或调整权限控件。

## 验证

- `node --test test/traffic.test.js`：旧库升级、重复迁移、失败回滚重试、账号/单 Key 区分、伪造头、真实 HTTP、429/配额、日志留存、并发口径、密钥绑定、请求快照、独立最大耗时、数据库故障重试、持久重启和清理保留。
- `node scripts/check-traffic-ui.js`：调用本地内存合成预览及已安装的 Playwright/Chromium，验证10次业务（含2次未分类历史）/6次内部/16次全部、CSV、明细、配置只读、错误重试、鉴权、390px/320px和键盘操作。可通过 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_PATH` 指定本机依赖，不给应用增加依赖。
- `node scripts/traffic-preview.js`：仅监听127.0.0.1的合成预览，不加载巡检、预热、推送调度器或生产数据；预览登录路由仅在手动运行此脚本时存在，不在正常服务中注册。
